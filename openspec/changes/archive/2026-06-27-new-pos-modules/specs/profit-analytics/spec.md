# Spec: Profit Analytics Module

**Change**: new-pos-modules
**Feature**: profit-analytics
**Version**: 1.0
**Date**: 2026-06-27

---

## Purpose

Define what must be true after the profit-analytics feature is implemented. This spec covers the IProfitQueryService port, gross margin calculations, top-selling products report, period comparison, payment-platform breakdown, and the prerequisite OperationalReportQueryService rewrite to use DB-side aggregation.

---

## Prerequisite Requirement

### R-PA-PRE-01: OperationalReportQueryService must use DB-side EF GroupBy before profit data is added

Before any profit aggregation query is added, the existing `OperationalReportQueryService` (or its equivalent) must be rewritten to push all GroupBy and aggregate operations to SQLite via EF Core's `IQueryable` GroupBy. In-memory loading (`.ToList()` before aggregation) must be eliminated.

**Testable assertion:** Integration tests must confirm that the SQL generated by the rewritten service contains `GROUP BY` clauses and does NOT load a full unsummarized dataset into memory before summing.

---

## Application Layer Requirements

### R-PA-01: IProfitQueryService port is defined in POS.Application

A port interface `IProfitQueryService` must be declared in POS.Application (not in Infrastructure or Presentation).

**Required methods:**
```
Task<IReadOnlyList<ProductMarginDto>> GetGrossMarginByProductAsync(DateRange period, CancellationToken ct = default);
Task<PeriodMarginDto> GetGrossMarginByPeriodAsync(DateRange period, CancellationToken ct = default);
Task<IReadOnlyList<TopSellerDto>> GetTopSellingProductsAsync(DateRange period, int topN, CancellationToken ct = default);
Task<PeriodComparisonDto> GetPeriodComparisonAsync(DateRange currentPeriod, DateRange priorPeriod, CancellationToken ct = default);
Task<IReadOnlyList<PaymentPlatformBreakdownDto>> GetPaymentPlatformBreakdownAsync(DateRange period, CancellationToken ct = default);
```

---

### R-PA-02: Gross margin formula is applied consistently

The gross margin per product line must use:

```
GrossMargin = (SalePrice - CostPrice) × UnitsSold
```

Where:
- `SalePrice` = the price at which the product was sold (from SaleItem).
- `CostPrice` = the cost price recorded on the Product entity at time of query (note: historical cost drift is out of scope for MVP).
- `UnitsSold` = total units sold for the product in the given period.

This formula must be applied in Application/Infrastructure, never recomputed in the ViewModel.

---

### R-PA-03: ProductMarginDto carries required fields

Each `ProductMarginDto` must include:
- `ProductId` (Guid)
- `ProductName` (string)
- `UnitsSold` (int)
- `TotalRevenue` (decimal) — sum of SaleItem line totals
- `TotalCost` (decimal) — CostPrice × UnitsSold
- `GrossMargin` (decimal) — TotalRevenue - TotalCost
- `MarginPercent` (decimal) — GrossMargin / TotalRevenue × 100 (0 when TotalRevenue = 0)

---

### R-PA-04: TopSellerDto carries required fields

Each `TopSellerDto` must include:
- `Rank` (int) — 1-based position
- `ProductId` (Guid)
- `ProductName` (string)
- `UnitsSold` (int)
- `TotalRevenue` (decimal)

Default sort: by `UnitsSold` descending. A secondary sort by `TotalRevenue` descending breaks ties.

---

### R-PA-05: PeriodComparisonDto carries required fields

`PeriodComparisonDto` must include:
- `CurrentPeriodRevenue` (decimal)
- `PriorPeriodRevenue` (decimal)
- `RevenueDelta` (decimal) — CurrentPeriodRevenue - PriorPeriodRevenue
- `RevenueDeltaPercent` (decimal) — RevenueDelta / PriorPeriodRevenue × 100 (null/special when PriorPeriodRevenue = 0)
- `CurrentPeriodGrossMargin` (decimal)
- `PriorPeriodGrossMargin` (decimal)
- `MarginDelta` (decimal)
- `MarginDeltaPercent` (decimal)

---

### R-PA-06: PaymentPlatformBreakdownDto carries required fields

Each `PaymentPlatformBreakdownDto` must include:
- `Platform` (string) — one of: "Nequi", "Bancolombia", "Daviplata", "Efectivo"
- `TransactionCount` (int)
- `TotalAmount` (decimal)
- `PercentOfTotal` (decimal) — TotalAmount / SUM(all platforms TotalAmount) × 100

---

## Infrastructure Requirements

### R-PA-07: IProfitQueryService implementation uses EF GroupBy pushed to SQLite

The `ProfitQueryService` implementation in POS.Infrastructure must:
- Use `IQueryable<T>` GroupBy so EF Core translates the aggregation to a SQL `GROUP BY` clause.
- Never call `.ToList()` or `.AsEnumerable()` before performing the grouping or sum.
- Apply date range filter (`WHERE SaleDate >= start AND SaleDate < end`) in the SQL predicate.

---

## Presentation Requirements

### R-PA-08: Profit analytics extend the existing Reports module

The profit analytics data surfaces inside the existing ReportsViewModel / Reports screen as additional tabs or sections. No new top-level sidebar entry is created for profit analytics.

**Required UI sections:**
- Top Sellers table (configurable N; default 10; rank, product name, units sold, revenue).
- Period Comparison panel (this week vs last week; this month vs last month).
- Payment Platform Breakdown table (platform, count, amount, % of total).
- Gross Margin per day table (date, revenue, cost, margin).

## Acceptance Scenarios

### Scenario PA-S1: Gross margin calculated correctly for a single product

```
GIVEN ProductX with CostPrice = $5,000 COP
AND ProductX was sold 3 times in the current period:
  - Sale1: 2 units at $8,000 COP each  → line total $16,000
  - Sale2: 1 unit at $8,000 COP        → line total $8,000
WHEN GetGrossMarginByProductAsync is called for the current period
THEN ProductMarginDto for ProductX has:
  UnitsSold = 3
  TotalRevenue = $24,000 COP
  TotalCost = $5,000 × 3 = $15,000 COP
  GrossMargin = $9,000 COP
  MarginPercent = 37.5%
```

### Scenario PA-S2: Product with no sales in period returns 0 margin

```
GIVEN ProductY with CostPrice = $3,000 COP
AND ProductY has no SaleItem records in the requested date range
WHEN GetGrossMarginByProductAsync is called for that period
THEN ProductY is NOT included in the result list (excluded, not returned as 0)
```

### Scenario PA-S3: Top sellers returns top N products by units sorted correctly

```
GIVEN in the current week:
  - ProductA sold 50 units
  - ProductB sold 30 units
  - ProductC sold 30 units, higher revenue than ProductB
  - ProductD sold 10 units
  - (other products)
WHEN GetTopSellingProductsAsync is called with topN=3
THEN the result contains exactly 3 entries
AND Rank 1 = ProductA (50 units)
AND Rank 2 = ProductC (30 units, higher revenue, wins tiebreak)
AND Rank 3 = ProductB (30 units)
```

### Scenario PA-S4: Period comparison shows correct deltas

```
GIVEN this week's sales total = $800,000 COP with GrossMargin = $200,000 COP
AND last week's sales total = $500,000 COP with GrossMargin = $150,000 COP
WHEN GetPeriodComparisonAsync is called with currentPeriod = this week, priorPeriod = last week
THEN PeriodComparisonDto has:
  CurrentPeriodRevenue = $800,000
  PriorPeriodRevenue = $500,000
  RevenueDelta = $300,000
  RevenueDeltaPercent = 60.0%
  CurrentPeriodGrossMargin = $200,000
  PriorPeriodGrossMargin = $150,000
  MarginDelta = $50,000
  MarginDeltaPercent = 33.33%
```

### Scenario PA-S5: Period comparison with zero prior period revenue

```
GIVEN last week's sales total = $0 COP (no sales)
AND this week's sales total = $200,000 COP
WHEN GetPeriodComparisonAsync is called
THEN RevenueDeltaPercent is null or a sentinel value indicating "N/A" (not a divide-by-zero exception)
AND the Application layer returns this result without throwing
```

### Scenario PA-S6: Payment platform breakdown sums each platform correctly

```
GIVEN in the current period:
  - 3 Nequi payments totaling $150,000 COP
  - 2 Bancolombia payments totaling $100,000 COP
  - 0 Daviplata payments
  - 5 Efectivo payments totaling $250,000 COP
  - Grand total = $500,000 COP
WHEN GetPaymentPlatformBreakdownAsync is called
THEN the result contains 3 entries (Daviplata excluded or included with 0)
AND PaymentPlatformBreakdownDto for "Nequi" has TotalAmount=$150,000, PercentOfTotal=30%
AND PaymentPlatformBreakdownDto for "Bancolombia" has TotalAmount=$100,000, PercentOfTotal=20%
AND PaymentPlatformBreakdownDto for "Efectivo" has TotalAmount=$250,000, PercentOfTotal=50%
```

### Scenario PA-S7: OperationalReportQueryService generates DB-side SQL

```
GIVEN the rewritten OperationalReportQueryService
WHEN a report aggregation query is executed
THEN the EF Core SQL log contains a GROUP BY clause
AND no intermediate .ToList() or .AsEnumerable() call precedes the GROUP BY-bearing query
(verified via integration test with in-memory SQLite or SQL log capture)
```

### Scenario PA-S8: Profit data visible in the Reports module

```
GIVEN a user with Reports access navigates to the Reports screen
WHEN the user selects the "Utilidades" or "Profit" section
THEN the Top Sellers table loads with the top 10 products for the current week
AND the Period Comparison panel shows this week vs last week figures
AND the Payment Breakdown table shows platform totals
AND the Gross Margin per day table shows daily data for the selected range
```

---

## Constraints and Non-Goals

- Historical cost tracking per sale item is out of scope; the current Product.CostPrice is used as-is.
- Charts (bar, line) for the profit analytics are optional in the Reports module UI — tabular data is the required baseline.
- No export-to-Excel/PDF for profit reports is required in this slice (export for other reports remains unchanged).
