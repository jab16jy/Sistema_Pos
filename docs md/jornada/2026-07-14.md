# Jornada — 2026-07-14

### Resumen ejecutivo
Se corrigió la regla de stock mínimo para que el estado "stock bajo" se refleje correctamente en Caja e Inventario, y se diagnosticó y solucionó por qué el agente Pi no mostraba los diffs reales de sus ediciones de código.

### Cambios en la app
- Unificada la regla de "stock bajo": ahora exige `MinimumStock > 0 && CurrentStock > 0 && CurrentStock <= MinimumStock`, en vez de la comparación simple anterior (`CurrentStock <= MinimumStock`).
- `ProductSearchResult` expone las propiedades calculadas `IsLowStock` e `IsOutOfStock`.
- El repositorio de inventario calcula `IsLowStock` con la misma regla para `StockLevelResult`.
- Los ViewModels de Inventario y Productos usan la propiedad `IsLowStock` en vez de recalcular la comparación de forma inline.
- Las vistas XAML de Inventario y Productos bindean sus `DataTrigger` a `IsLowStock` / `IsOutOfStock` en vez de comparar `CurrentStock` directamente.
- Tests nuevos/ajustados: cobertura del dominio, de los ViewModels de Inventario/Productos y de la búsqueda de Caja (48 tests en verde).

### Archivos y módulos afectados
- `src/POS.Domain/Entities/Product.cs` — método `IsLowStock()` corregido (fuente de verdad del dominio).
- `src/POS.Application/DTOs/Products/ProductCatalogDtos.cs` — nuevas propiedades calculadas `IsLowStock`/`IsOutOfStock` en `ProductSearchResult`.
- `src/POS.Infrastructure/Persistence/Repositories/InventoryRepository.cs` — cálculo de `IsLowStock` en el query de `StockLevelResult`.
- `src/POS.Presentation.Shared/ViewModels/InventoryViewModel.cs` y `ProductsViewModel.cs` — uso de la propiedad unificada.
- `src/POS.Presentation/Views/InventoryView.xaml` y `ProductsView.xaml` — triggers visuales actualizados.
- `tests/POS.Domain.Tests/ProductTests.cs`, `tests/POS.Presentation.Shared.Tests/CashierViewModelTests.cs`, `InventoryViewModelTests.cs`, `ProductsViewModelTests.cs` — cobertura nueva/ajustada.
- `.gitignore` — se agregó `.pi/gentle-ai/` para ignorar el cache local de la extensión gentle-ai.

### Decisiones relevantes
- El estado "stock bajo" solo debe mostrarse cuando el mínimo está configurado (`MinimumStock > 0`) y el producto tiene existencia (`CurrentStock > 0`) — Por qué: antes, un mínimo sin configurar (0) o un producto agotado se marcaban incorrectamente como "stock bajo" en vez de "sin stock" o estado neutro.
- `CashierProductSearchResultViewModel` (Caja) ya tenía la lógica correcta antes del fix; se usó como referencia y solo se le agregó un test de regresión para stock agotado.
- Se restauró el renderizado nativo de diffs en Pi seteando `GENTLE_PI_QUIET_TOOLS=0` como variable de usuario permanente — Por qué: la extensión `gentle-pi` (`npm:gentle-pi`, `quiet-tools.ts`) reemplaza el render de `edit`/`write` con uno propio que solo lee el contenido de texto plano del resultado, descartando el diff estructurado nativo incluso al expandir con Ctrl+O.

### Bugs
**Corregidos:**
- Stock bajo no se reflejaba correctamente en Caja e Inventario (root cause: `IsLowStock()` no exigía mínimo configurado ni stock positivo).
- Pi no mostraba el diff real de las ediciones de código (root cause: la extensión `gentle-pi` registra un renderer silencioso para `edit`/`write` que descarta el diff nativo).
