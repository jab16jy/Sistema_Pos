### Decisiones relevantes
- Mantener la implementación en WPF-only y no reabrir Avalonia - Por qué: la decisión vigente del proyecto ya consolidó Windows + WPF como stack principal.
- Desactivar Strict TDD en OpenSpec para este cambio - Por qué: el usuario pidió seguir con implementación y verify sin el modo estricto.
- Usar variables de entorno en vez de construir ahora el módulo completo de `SystemConfiguration` - Por qué: permitió cerrar huecos runtime sin expandir el alcance al módulo de Ajustes.
- Mantener commits por fase - Por qué: mejora la trazabilidad y deja slices revisables del trabajo.

### Bugs
**Corregidos:**
- Falla potencial al construir `SmtpEmailService` en WPF por dependencia de `IConfiguration` inexistente (root cause: el composition root no registraba configuración compatible con ese servicio).
- Envío de WhatsApp atado a `/bin/bash` en un proyecto WPF para Windows (root cause: el adaptador asumía shell Unix en vez de proceso configurable).
- `ReportService` y `PrintService` lanzaban `NotImplementedException` en módulos ya expuestos como implementados (root cause: servicios stub sin comportamiento runtime mínimo).
- Caja y Cotizaciones seguían usando lookup prototipo pese a tener infraestructura SQLite disponible (root cause: faltaba un `IProductLookupService` persistido y su wiring en WPF).

**Pendientes:**
- La configuración runtime todavía depende de variables de entorno; el módulo de Ajustes/SystemConfiguration sigue pendiente.
- Sigue pendiente ordenar y stagear la mudanza documental `md/` -> `docs md/`, que no se tocó en esta jornada.
